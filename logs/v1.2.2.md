# v1.2.2 - Fix Crítico: App no carga (pantalla blanca)

**Fecha**: 09/09/2026

---

## Descripción

Corrección del bug crítico que impedía que la aplicación cargara, mostrando una pantalla blanca con el mensaje "página web no disponible".

---

## Problema Reportado

**Mensaje de error**:
```
página web no disponible
La pagina web de https://localhost/ no se pudo cargar porque: 
net:ERR_CONNECTION_REFUSED
```

**Síntoma**: La app mostraba pantalla blanca en lugar del splash screen.

---

## Causa Raíz

El `AdBlockWebViewClient` estaba extendiendo `WebViewClient` de Android en lugar de `BridgeWebViewClient` de Capacitor.

```java
// PROBLEMÁTICO - Reemplazaba el WebViewClient de Capacitor
private class AdBlockWebViewClient extends WebViewClient {
    ...
}
```

Cuando se reemplaza el WebViewClient de Capacitor, se pierde la capacidad de cargar archivos locales (`file://`), y el WebView intenta cargar desde `https://localhost` que no existe.

---

## Solución

Extender `BridgeWebViewClient` de Capacitor en lugar de `WebViewClient` de Android:

```java
// CORRECTO - Mantiene la funcionalidad de Capacitor
private class AdBlockWebViewClient extends BridgeWebViewClient {
    public AdBlockWebViewClient(com.getcapacitor.Bridge bridge) {
        super(bridge);
    }
    ...
}
```

Y al inicializar:
```java
// ANTES
webView.setWebViewClient(new AdBlockWebViewClient());

// DESPUÉS
webView.setWebViewClient(new AdBlockWebViewClient(getBridge()));
```

## Lección Aprendida

Al extender clases de WebView en Capacitor, SIEMPRE se debe extender las clases de Capacitor (`BridgeWebViewClient`, `BridgeChromeClient`) en lugar de las clases nativas de Android. De lo contrario, se pierde la funcionalidad de carga de archivos locales.

---

## Nota

Este bug fue causado por la implementación anterior del ad-blocking que reemplazaba completamente el WebViewClient de Capacitor. La solución mantiene toda la funcionalidad de ad-blocking mientras preserva la capacidad de cargar archivos locales.
