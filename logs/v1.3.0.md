# v1.3.0 - Reestructuración: Navegador Nativo (fix páginas y ad-block)

**Fecha**: 09/09/2026

---

## Descripción

Corrección de raíz de dos problemas críticos: **las páginas web no cargaban** y **los anuncios no se bloqueaban**. Se rediseñó la forma de mostrar los sitios: se eliminó el `<iframe>` dentro de la app y ahora cada sitio se carga **como documento principal (top-level)** en un **WebView nativo dedicado** (overlay), donde el bloqueador de anuncios sí actúa sobre la página real.

---

## Causas Raíz Detectadas

### 1. Los sitios no cargaban (arquitectura de iframe)
- `animeonline.ninja` envía `X-Frame-Options: SAMEORIGIN` (verificado con `curl`): un navegador bloquea mostrarlo dentro de un iframe de otro origen.
- Muchos sitios usan frame-busting por JS o `Content-Security-Policy: frame-ancestors`.
- El iframe usaba `sandbox` + `referrerpolicy=no-referrer`, lo que rompe cookies, logins y reproductores.

### 2. Los anuncios no se bloqueaban (límite cross-origin)
- La documentación anterior ya lo admitía (`docs/04`): **no se puede inyectar JS/CSS en iframes cross-origin**. Por eso las capas CSS/JS corrían en la página local de la app y nunca en el sitio.

### 3. Falsos positivos por matcheo de substrings en `isAdUrl()`
- `lowerUrl.contains(domain)` con dominios cortos bloqueaba sitios legítimos. Ejemplo: `turn.com` bloqueaba `return.com`; `tag.com` bloqueaba `sometag.com`.
- **Solución**: ahora se compara el **host** de la URL con el dominio por igualdad exacta o sufijo (`.dominio`). Se eliminó el bloqueo por keywords de URLs (propenso a falsos positivos).

### 4. Inyección CSS rota por escaping de comillas en Java
- `String.replace("'", "\\'")` solo reemplaza la **primera** comilla; el CSS tenía muchas, el JS resultaba inválido y la inyección fallaba en silencio.
- **Solución**: el CSS se inyecta **codificado en Base64** y se decodifica con `atob()` en la página. Sin problemas de escaping.

---

## Solución Implementada

### Navegador nativo en overlay
- Al tocar un sitio, el JS envía `window.location = 'danganime://open?url=...&title=...'`.
- `MainActivity` intercepta el esquema `danganime://` (en `AppSchemeClient`, subclase de `BridgeWebViewClient`) y muestra un **WebView nativo de pantalla completa** encima de la app.
- El sitio se carga como documento principal → sin restricciones de iframe.
- El ad-blocker se aplica a ese WebView:
  - `shouldInterceptRequest`: bloqueo de red por host.
  - `onPageFinished`: inyección de CSS cosmético (Base64) y JS (fetch/XHR/MutationObserver).
- Barra de herramientas nativa: ← retroceder, ↻ recargar, ⛶ ocultar/mostrar barra (fullscreen), ↗ abrir externo, × cerrar y volver al menú.
- Botón atrás del sistema: retrocede en el historial y, si no hay más, cierra el navegador.

### Seguridad de matching de dominios
```java
if (host.equals(d) || host.endsWith("." + d)) return true; // ya NO substring
```

### Comunicación JS -> Nativo sin plugins
- Se usa un esquema de URL propio (`danganime://`) interceptado en `shouldOverrideUrlLoading`, evitando el riesgo de reemplazar el WebViewClient de Capacitor (lección de v1.2.2).
